公開までの順序

  1. 社員さんが文面と実運用を確認し、必要な修正を返す。利用規約のLINE受領方法・申込み有効期間・案内PDFの扱いも確認する。
  2. プラポリを修正した場合は、求職者フォームで記録する同意文面の版も更新し、ページとフォームで整合を確認する。
  3. 公開予定URLを確定する。第一候補は https://career.head-hunter.jp/terms と https://career.head-hunter.jp/privacy。
  4. GitHubの権限者が takariku0822 のLPリポジトリへの書き込み権限を確認する。現時点のAPI確認ではpush=false。権限が付くまで別アカウントや別経路でpushしない。
  5. 最新mainとの差分、CI、レビュー、HEAD SHAを確認し、Draft PRを作成・更新する。権限者の明示的な公開・マージ承認後にsquash mergeする。
  6. Git連携の配布が完了したことを確認する。重複する手動Vercelデプロイは行わない。
  7. 本番の両ページが200で表示されること、LPフッターから移動できること、本文・メタ情報・会社情報が承認版と一致することを読み取り確認する。フォームへ未公開URLは設定しない。
  8. 公開確認済みプラポリURLを使って、L Harnessのフォーム説明をリンク表示へ切り替える。フォーム側のPR #712のレビュー・既存チェックの問題解消・公開承認も別途必要。

フォームへのURL設定はすぐに生成できる

L Harnessに、承認・公開確認済みURLを引数として受け取り、対象フォームの説明文だけを更新するSQL生成ツールを用意しました。

node ops/referral-consultation-privacy-link.mjs <承認・公開確認済みURL>

SQLを表示するだけで、本番への接続・適用・フォーム有効化は行いません。初回のフォーム設定を作成した後、権限者が生成SQLを確認して適用します。対象フォームIDとLINEアカウントIDの両方で範囲を限定し、設問・同意必須・紹介情報・既存回答は変更しません。

リンクを開いたかどうかは送信条件にしません。閲覧しなくても、必須の「同意する」を回答すれば先へ進めます。

不具合が見つかった場合

フォームは既存手順で無効化し、従来の入口パックへ戻します。保存済み回答を削除しません。法務ページを戻す場合は問題と影響を確認し、元のGitコミットを特定して通常のrevert PRで対応します。force pushやmainの履歴改変は行いません。
